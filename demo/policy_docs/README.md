# Demo: policy documents (the "no, don't fine-tune" case)

Q&A pairs for support agents at Brightlane, a fictional home-goods retailer. Every
answer is a fact recalled from one of the policy documents in [docs/](docs/): return
windows, fees, warranty terms, support hours. These facts change whenever a policy is
updated, which makes this a knowledge gap. Retrieval over `docs/` fits better than
baking the facts into model weights.

Each row has a `source` field naming the document the answer comes from. The data is
generated by [generate.py](generate.py) (the output is identical on every run).

| Rows | Count |
|---|---|
| Clean (36 facts × 6 question phrasings) | 216 |
| Duplicates | 12 |
| Low-quality (refusals, placeholders) | 5 |
| Malformed | 3 |
| **Total** | **236** |

```bash
trainjudge diagnose --dataset demo/policy_docs/data.jsonl --model Qwen3-0.6B \
  --goal "make it answer from our internal support policy documents"
trainjudge audit demo/policy_docs/data.jsonl
python demo/policy_docs/generate.py   # regenerate
```
